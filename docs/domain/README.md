# 도메인 개요

이 폴더는 찜꽁의 **도메인 모델** — 이 서비스가 다루는 개념들이 각각 무엇이고, 서로
어떤 관계이며, 어떤 규칙이 그 관계를 지탱하는지 — 를 설명한다.

코드의 구조나 실행 방법은 루트의 [AGENTS.md](../../AGENTS.md)에 있다. 여기서는
"왜 이 개념이 이렇게 생겼는가"만 다룬다.

## 한 문장

찜꽁은 **사용자가 붙여넣은 링크에서 실제로 방문할 수 있는 장소를 뽑아내
지도에 꽂아 두는 서비스**다.

도메인 전체가 그 문장에서 파생된다. 링크는 장소의 *출처*이고, 장소는 링크의 *결과*이며,
사용자는 그 둘의 묶음을 소유한다.

## 도메인 지도

```
                   ┌──────────────┐
                   │ UserProfile  │  사람 하나
                   │  (사람)      │
                   └──────┬───────┘
                          │ 소유
        ┌─────────────────┼─────────────────┐
        │                 │                 │
  ┌─────▼──────┐   ┌──────▼──────┐   ┌──────▼──────┐
  │AuthIdentity│   │  SavedPost  │   │   Session   │
  │ 소셜 로그인 │   │ 저장한 링크  │   │ 로그인 브라우저│
  └────────────┘   └──────┬──────┘   └─────────────┘
                          │ SavedPostPlace (+메모)
                   ┌──────▼──────┐
                   │    Place    │  전역 공유 — 특정 사용자의 것이 아니다
                   └─────────────┘
```

**소유의 경계가 곧 도메인의 핵심 구분선이다.** `SavedPost`는 사용자의 것이고
`Place`는 아무의 것도 아니다. 이 비대칭이 이 도메인에서 가장 자주 오해받는 지점이며,
[aggregates.md](aggregates.md)와 [invariants.md](invariants.md)가 그 이유를 다룬다.

## 두 개의 하위 도메인

찜꽁은 성격이 전혀 다른 두 하위 도메인으로 나뉜다.

**인제스트 (핵심 도메인)** — 링크에서 장소를 만들어 낸다. 이 서비스가 존재하는
이유이자 경쟁력이 있는 부분이고, 동시에 **전부 외부 시스템에 의존하는** 부분이다
(인스타그램·유튜브·LLM·네이버 지역검색). 그래서 이 도메인의 규칙은 대부분
"외부가 실패했을 때 무엇이 참인가"를 정의한다.

**신원 (지원 도메인)** — 누가 무엇을 소유하는지 정한다. 제품 차별점은 없지만
틀리면 남의 데이터가 새는 부분이다. 여기의 규칙은 대부분 "무엇을 믿지 않는가"를
정의한다 — 클라이언트가 보낸 좌표도, 제공자가 말한 전화번호 인증도 믿지 않는다.
