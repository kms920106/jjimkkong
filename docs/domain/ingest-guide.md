# 링크를 붙여넣으면 무슨 일이 일어날까?

이 문서는 개발자가 아니어도 읽을 수 있도록, "링크 붙여넣기 → 지도에 핀 찍기"가
내부적으로 어떤 단계를 거치는지 쉬운 말로 설명합니다. 코드 이름이나 파일 경로 같은
개발 세부사항이 필요하면 같은 폴더의 [ingest.md](ingest.md)를 참고하세요.

## 한눈에 보는 전체 과정

```
①  인스타그램/유튜브 링크 붙여넣기
        │
②  그 게시글의 글(캡션)과 사진을 가져온다
        │
③  AI가 글을 읽고 "여기 가면 좋겠다" 싶은 장소 이름을 뽑아낸다
        │
④  네이버 지도에 그 이름을 검색해서 실제 위치(좌표)를 찾는다
        │
⑤  사용자에게 결과를 보여주고, "저장" 누르면 지도에 핀이 찍힌다
```

**가장 중요한 원칙: ⑤에서 사용자가 저장을 누르기 전까지는 아무것도 저장되지
않습니다.** AI도 틀릴 수 있고, 지도 검색도 엉뚱한 곳을 찾을 수 있기 때문에,
최종적으로 맞는지 확인하는 건 항상 사람(사용자)입니다.

## 어떤 링크를 넣을 수 있나요?

| 종류 | 예시 |
|---|---|
| 인스타그램 게시물/릴스 | `instagram.com/reel/...`, `/p/...` |
| 유튜브 영상/쇼츠 | `youtube.com/watch?v=...`, `youtu.be/...` |
| 네이버 지도 장소 | `map.naver.com/...`, `naver.me/...` |
| 카카오맵 장소 | `place.map.kakao.com/...`, `kko.to/...` |

이 4가지 외의 링크(예: 블로그, 트위터, 일반 웹사이트)는 넣을 수 없고 오류가 납니다.
왜냐하면 이 서비스는 "이 사이트에서는 이렇게 글을 읽어와야 한다"는 방법을 각
플랫폼마다 따로 알고 있어야 하는데, 모르는 사이트는 그 방법 자체가 없기 때문입니다.

## 같은 링크를 두 번 저장해도 괜찮은 이유

인스타그램 게시물 하나는 사실 `/p/`, `/reel/`, `/reels/`, `/tv/` 같은 여러 가지
주소로도 열 수 있고, 링크를 공유할 때 뒤에 알 수 없는 문자(`?igsh=...`)가 붙기도
합니다. 서비스는 이런 차이를 자동으로 정리해서 "같은 게시글"로 알아보기 때문에,
친구가 살짝 다른 형태로 보낸 같은 링크를 붙여넣어도 중복으로 쌓이지 않고 하나로
합쳐집니다.

## 두 가지 경로: "게시글"과 "지도 링크"는 다르게 처리됩니다

- **인스타그램·유튜브 같은 "게시글"**은 여러 장소를 글 속에서 자연스럽게
  언급합니다. 예를 들어 "성수동 대림창고 다녀왔어요, 근처 카페 ○○도 좋아요"처럼
  여러 곳이 한 글에 섞여 있을 수 있어서, **AI가 글을 읽고 어떤 단어가 실제
  장소인지 판단**합니다.
- **네이버·카카오 지도 링크**는 애초에 장소 하나를 정확히 가리키고 있습니다.
  이미 정답을 알고 있으니 AI에게 다시 물어볼 필요가 없어서, 이 경우엔 AI 단계를
  건너뛰고 곧바로 위치를 찾습니다.

## ②단계: 글(캡션) 가져오기 — 왜 실패할 때가 있나요?

- **유튜브**: 영상 설명글을 가져올 수 있으면 가져오고, 못 가져오면 사용자가
  직접 설명을 붙여넣도록 안내합니다.
- **인스타그램**: 사람이 브라우저로 보는 것과 서비스가 자동으로 읽어오는 방식이
  달라서, 가끔 인스타그램이 내용을 안 보여줄 때가 있습니다. 이럴 때도 사용자가
  글을 직접 붙여넣을 수 있는 입력창이 뜹니다.

즉, 자동으로 못 가져와도 서비스가 멈추는 게 아니라 "직접 붙여넣어 주세요"로
넘어갑니다.

## ③단계: AI가 장소 이름을 골라내는 기준

AI에게 아래처럼 시켰습니다.

- **뽑아야 하는 것**: 식당, 카페, 바, 가게, 숙소, 관광지, 공연장처럼 실제로
  찾아가서 방문할 수 있는 곳.
- **뽑지 말아야 하는 것**: 브랜드 이름, 메뉴 이름, 사람·계정 이름, 해시태그,
  그리고 "서울"이나 "제주"처럼 너무 넓어서 지도에 핀 하나로 찍을 수 없는 지역.

글에 나온 장소가 없으면 AI는 빈 결과를 줄 뿐, 없는 장소를 지어내지 않습니다.
한 게시글에서 뽑을 수 있는 장소는 **최대 20개**까지입니다.

## ④단계: 저장하기 전 마지막 확인

여기까지 온 결과는 화면에 후보로만 보이고, 사용자가 "저장" 버튼을 눌러야 실제로
지도에 핀이 찍힙니다. 이때 두 가지 안전장치가 있습니다.

- **좌표는 항상 서비스가 다시 확인합니다.** 혹시라도 잘못된 위치 정보가 몰래
  들어와서 다른 사람이 이미 등록한 장소의 핀을 옮겨버리는 일이 없도록,
  사용자가 이름만 넘기면 위치는 서버가 새로 찾아서 확정합니다.
- **찾은 장소가 하나도 없으면 저장 자체가 안 됩니다.** 지도에 아무것도 표시되지
  않는 저장은 이 서비스가 하려는 일(지도에 핀 찍기)이 아니기 때문입니다.

## 요약

1. 링크를 붙여넣으면 서비스가 그 게시글의 내용을 최대한 자동으로 읽어옵니다.
2. 읽어온 글에서 AI가 "가볼 만한 장소" 이름만 골라냅니다 (지도 링크는 이 단계
   건너뜀).
3. 그 이름들을 지도 검색으로 실제 위치로 바꿉니다.
4. 사용자가 결과를 확인하고 저장을 눌러야 비로소 지도에 핀이 찍힙니다.
