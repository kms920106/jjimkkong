# 구글맵 JavaScript SDK 설정 가이드

코드는 이미 다 들어가 있다([frontend/src/components/map/GoogleMap.tsx](../../frontend/src/components/map/GoogleMap.tsx),
[frontend/src/lib/map/loader.ts](../../frontend/src/lib/map/loader.ts)). 이 문서는 **콘솔에서
해야 하는 일**과 그 결과를 어디에 넣는지만 다룬다. 코드 쪽 이유는 루트
[AGENTS.md](../../AGENTS.md)의 "지도" 절과
[frontend/src/lib/map/AGENTS.md](../../frontend/src/lib/map/AGENTS.md)에 있다.

`NEXT_PUBLIC_GOOGLE_MAPS_KEY`는 선택 항목이다. 없어도 앱은 정상 동작한다 — 기본 제공자가
네이버이므로, 이 키가 비어 있으면 `/settings`에서 구글맵을 고른 사용자만 지도 대신
`MapLoadError`를 본다.

**이 키는 지도 렌더링 전용이다.** 게시글에서 장소를 추출하고 좌표를 조회하는 인제스트
파이프라인은 네이버 지역검색을 쓰므로 이 키와 무관하다 — 이 키가 없어도 링크 저장과 장소
지오코딩은 정상 동작한다. 다만 카카오와 달리 **구글맵은 유료 API라서, 이 키가 실제로 도는
동안은 과금 계정 연결이 필요하다.**

## 1. 구글 클라우드 프로젝트 생성

https://console.cloud.google.com 로그인 → 상단 프로젝트 선택기 → "새 프로젝트".

| 항목 | 값 |
|------|-----|
| 프로젝트 이름 | 식별용, 아무 이름(예: `jjimkkong`) |

이미 이 앱에서 다른 구글 API(예: 유튜브 Data API)를 위해 만든 프로젝트가 있다면 그 프로젝트를
재사용해도 된다 — API마다 켜고 끄는 단위이지 프로젝트를 나눌 필요는 없다.

## 2. 결제 계정 연결

**이 단계를 건너뛰면 API를 켜도 요청이 막힌다.** Maps JavaScript API는 무료 크레딧(월
$200, 2026년 기준)이 있지만 그 크레딧을 받으려면 여전히 결제 계정이 프로젝트에 연결돼
있어야 한다. 좌측 메뉴 "결제" → 이 프로젝트에 결제 계정 연결(신규라면 카드 등록).

무료 크레딧 한도 안에서는 청구가 발생하지 않지만, **한도를 넘기면 실제로 과금된다.**
예산 알림(결제 → 예산 및 알림)을 걸어 두는 것을 권한다 — 코드가 이 한도를 감시하지
않는다.

## 3. Maps JavaScript API 사용 설정

좌측 메뉴 "API 및 서비스" → "라이브러리" → "Maps JavaScript API" 검색 → **사용**.

다른 Maps 계열 API(Places, Directions 등)는 이 앱이 쓰지 않으므로 켜지 않는다 — 켜 두면
공격 표면과 잠재 과금 항목이 늘어날 뿐 아무 코드도 그걸 호출하지 않는다.

## 4. API 키 발급 및 제한 설정

"API 및 서비스" → "사용자 인증 정보" → "사용자 인증 정보 만들기" → "API 키".

발급 즉시 키를 **제한**해야 한다. 제한하지 않은 키는 누구든 훔쳐서 자기 사이트에 붙이면
그 트래픽이 이 프로젝트의 결제 계정으로 청구된다.

발급된 키 → "키 제한사항":

- **애플리케이션 제한사항**: "HTTP 리퍼러(웹사이트)" 선택.
- **웹사이트 제한사항**에 다음을 등록:
  ```
  http://localhost:4000/*
  https://<배포-도메인>/*
  ```
  이 앱의 dev 서버는 3000이 아니라 **4000**이다(루트 [AGENTS.md](../../AGENTS.md)의
  "명령어" 참고). 배포 도메인을 빠뜨리면 로컬에서는 지도가 뜨고 프로덕션에서만 깨지는데,
  이건 이 저장소의 다른 지도 제공자들과 똑같은 함정이다 — 세 콘솔 모두
  `http://localhost:4000`과 배포 도메인이 등록돼 있어야 한다.
- **API 제한사항**: "키 제한" 선택 → "Maps JavaScript API"만 체크.

리퍼러 제한과 API 제한 둘 다 걸어야 한다. 하나만 걸면 그 키로 다른 도메인에서 이 API를
쓰거나, 이 도메인에서 다른 유료 API를 쓰는 경로가 그대로 열려 있다.

## 5. 로컬 환경변수

`frontend/.env`의 다음 줄에 붙여넣는다:

```
NEXT_PUBLIC_GOOGLE_MAPS_KEY=
```

`NEXT_PUBLIC_` 접두어가 붙은 값은 **클라이언트 번들에 그대로 실려 나간다.** 이 키는
그래야 하는 값이다(브라우저가 SDK를 로드한다). 그래서 이 키의 유일한 접근 제어는 4단계의
리퍼러 제한이고, 제한을 걸지 않으면 아무 사이트에서나 이 키로 지도를 띄워 이 프로젝트의
결제 계정에 청구할 수 있다.

값을 바꾼 뒤에는 **dev 서버를 재시작해야 한다.** `NEXT_PUBLIC_*`은 빌드 시점에 번들로
인라인되므로 HMR로는 반영되지 않는다.

## 6. 확인

```bash
cd frontend && npm run dev
```

1. http://localhost:4000 접속 → 로그인 → 좌측 상단 메뉴(`AppDrawer`) 열기.
2. "지도" 아래 **구글맵** 라디오 선택. 드로어가 닫히면서 뒤의 지도가 바뀐다
   (이 설정이 페이지가 아니라 드로어에 남아 있는 이유다 — 루트 [AGENTS.md](../../AGENTS.md)의
   "지도 제공자 선택만 drawer에 남는다" 참고).
3. 저장된 핀이 있으면 지도가 핀 전체를 프레임하는지, 핀을 눌러 출처 시트가 열리는지 확인.
4. `/links` 상세에서 장소를 눌러 홈으로 돌아왔을 때 그 핀으로 카메라가 이동하는지 확인.

**실패는 조용하지 않다.** 키가 비어 있으면 `NEXT_PUBLIC_GOOGLE_MAPS_KEY가 없습니다.`,
키·리퍼러 제한·API 사용 설정 중 무엇이 틀리면 `구글 지도 SDK를 초기화하지 못했습니다.
API 키와 허용 도메인을 확인해 주세요.`가 지도 자리에 뜬다. 그 문구만으로는 원인이
구별되지 않으므로, **브라우저 콘솔을 함께 볼 것** — `maps.googleapis.com/maps/api/js`
요청이 실패했거나 콘솔에 `RefererNotAllowedMapError`/`ApiNotActivatedMapError` 같은
구글 쪽 오류가 찍히면 각각 4단계·3단계가 원인이다.

## 7. 무료 여부

Maps JavaScript API는 월 $200 무료 크레딧이 있지만(2026년 기준, 구글이 언제든 바꿀 수 있는
값이다) 그 한도를 받으려면 2단계의 결제 계정 연결이 필요하고, 한도를 넘기면 실제로
과금된다. 카카오맵처럼 무조건 무료인 것이 아니므로 예산 알림을 걸어 두는 것을 권한다.
좌표를 이름으로 바꾸는 지오코딩은 이 앱에서 구글이 아니라 네이버 지역검색이 하므로, 이
키의 한도·과금과는 무관하다.
