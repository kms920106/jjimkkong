# 카카오맵 JavaScript SDK 설정 가이드

코드는 이미 다 들어가 있다([frontend/src/components/map/KakaoMap.tsx](../../frontend/src/components/map/KakaoMap.tsx),
[frontend/src/lib/map/loader.ts](../../frontend/src/lib/map/loader.ts)). 이 문서는 **콘솔에서
해야 하는 일**과 그 결과를 어디에 넣는지만 다룬다. 코드 쪽 이유는 루트
[AGENTS.md](../../AGENTS.md)의 "지도" 절과
[frontend/src/lib/map/AGENTS.md](../../frontend/src/lib/map/AGENTS.md)에 있다.

`NEXT_PUBLIC_KAKAO_MAP_KEY`는 선택 항목이다. 없어도 앱은 정상 동작한다 — 기본 제공자가
네이버이므로, 이 키가 비어 있으면 `/settings`에서 카카오맵을 고른 사용자만 지도 대신
`MapLoadError`를 본다.

**이 키는 지도 렌더링 전용이다.** 카카오 지도 링크(`place.map.kakao.com`, `kko.to`)를
붙여넣어 저장하는 인제스트 경로는 og 태그를 파싱할 뿐이라 키를 쓰지 않고, 좌표는 네이버
지역검색이 조회한다. 그래서 이 키가 없어도 카카오 링크 저장은 된다 — 그 결과를 *카카오
지도로 볼* 수 없을 뿐이다. `/links` 상세의 "카카오맵으로 열기" 버튼도 키와 무관하다
(외부 앱으로 나가는 URL이다).

## 1. 카카오 개발자 앱 생성

https://developers.kakao.com 로그인 → 상단 "내 애플리케이션" → "애플리케이션 추가하기".

| 항목 | 값 |
|------|-----|
| 앱 이름 | 식별용, 아무 이름(예: `jjimkkong`) |
| 사업자명 | 개인이면 본인 이름 |

**소셜 로그인용 앱과 같은 앱을 써도 된다.** `AuthProvider.KAKAO`는 이미 enum에 있지만
카카오 로그인은 아직 구현되지 않았다 — 나중에 붙일 때 이 앱에 카카오 로그인을 함께
활성화하면 되고, 그때 쓰는 키는 REST API 키라서 이 JavaScript 키와 다른 값이다.

## 2. 카카오맵 사용 설정 ON

**이 단계를 건너뛰면 3·4단계를 정확히 해도 401이 난다.** 공식 지도 가이드에는 이 단계가
없어서 놓치기 쉽고, 실제로 401 문의의 가장 흔한 원인이다.

내 애플리케이션 → 해당 앱 → 좌측 "제품 설정" → "카카오맵" → **사용 설정: ON**.

## 3. JavaScript SDK 도메인 등록

**등록된 도메인에서만 SDK가 동작한다. 포트가 있으면 포트까지 등록해야 한다.**
이 앱의 dev 서버는 3000이 아니라 **4000**이다(루트 [AGENTS.md](../../AGENTS.md)의 "명령어" 참고).

좌측 "앱 설정" → "앱" → **"플랫폼 키"** → "JavaScript 키" → **"JavaScript SDK 도메인"**.

**"앱 설정 → 플랫폼"이라고 적힌 안내를 따라가지 말 것.** 2025-12-03 콘솔 개편으로 웹
도메인 설정이 앱 단위에서 **앱 키 단위**로 내려갔고, 지금 좌측 메뉴에는 "플랫폼"이 없고
"플랫폼 키"만 있다. 인터넷에 남아 있는 대부분의 안내와 카카오 자신의 지도 가이드
일부가 아직 옛 경로를 적고 있다.

같은 개편으로 앱 키를 종류별 최대 5개까지 만들 수 있고 그중 하나가 **대표 키**다. 기존
앱은 쓰던 키가 자동으로 대표 키가 됐다. 키가 여럿이면 **`.env`에 넣은 그 키의 도메인
목록**에 등록해야 한다 — 다른 키에 등록해도 401은 그대로다.

`제품 링크 관리 → 웹 도메인`은 **다른 자리다.** 그쪽은 카카오톡 공유·메시지의 링크
연결용이고 지도 SDK 검증과 무관하다. 여기에 등록하고 지도가 안 뜬다고 하지 말 것.

등록할 값:

```
http://localhost:4000
https://<배포-도메인>
```

기본 포트(80/443)는 생략되지만 4000은 명시해야 한다. 배포 도메인을 빠뜨리면 로컬에서는
지도가 뜨고 프로덕션에서만 깨지는데, 이건 이 저장소의 다른 지도 제공자들과 똑같은 함정이다
— 세 콘솔 모두 `http://localhost:4000`과 배포 도메인이 등록돼 있어야 한다.

## 4. JavaScript 키 복사

3단계와 **같은 화면**(앱 설정 → 앱 → 플랫폼 키)의 "JavaScript 키" 상단에서 복사한다.

32자 hex 문자열이다. REST API 키·네이티브 앱 키·Admin 키가 같은 화면에 나란히 있으니
**JavaScript 키가 맞는지 확인할 것** — 다른 키를 넣으면 역시 401이다.

## 5. 로컬 환경변수

`frontend/.env`의 다음 줄에 붙여넣는다:

```
NEXT_PUBLIC_KAKAO_MAP_KEY=
```

`NEXT_PUBLIC_` 접두어가 붙은 값은 **클라이언트 번들에 그대로 실려 나간다.** 이 키는
그래야 하는 값이다(브라우저가 SDK를 로드한다). 그래서 이 키의 유일한 접근 제어는 3단계의
도메인 등록이고, 도메인 등록을 비워 두면 아무 사이트에서나 이 키로 지도를 띄울 수 있다.
Admin 키나 REST API 키를 실수로 이 자리에 넣지 말 것 — 그쪽은 노출되면 안 되는 값이다.

값을 바꾼 뒤에는 **dev 서버를 재시작해야 한다.** `NEXT_PUBLIC_*`은 빌드 시점에 번들로
인라인되므로 HMR로는 반영되지 않는다.

## 6. 확인

```bash
cd frontend && npm run dev
```

1. http://localhost:4000 접속 → 로그인 → 좌측 상단 메뉴(`AppDrawer`) 열기.
2. "지도" 아래 **카카오맵** 라디오 선택. 드로어가 닫히면서 뒤의 지도가 바뀐다
   (이 설정이 페이지가 아니라 드로어에 남아 있는 이유다 — 루트 [AGENTS.md](../../AGENTS.md)의
   "지도 제공자 선택만 drawer에 남는다" 참고).
3. 저장된 핀이 있으면 지도가 핀 전체를 프레임하는지, 핀을 눌러 출처 시트가 열리는지 확인.
4. `/links` 상세에서 장소를 눌러 홈으로 돌아왔을 때 그 핀으로 카메라가 이동하는지 확인.

**실패는 조용하지 않다.** 키가 비어 있으면 `NEXT_PUBLIC_KAKAO_MAP_KEY가 없습니다.`,
키·도메인·사용설정 중 무엇이 틀리면 `카카오맵을 불러오지 못했습니다.`가 지도 자리에 뜬다.
다만 그 문구만으로는 셋 중 어느 것인지 구별되지 않으므로, **브라우저 콘솔을 함께 볼 것** —
`dapi.kakao.com/v2/maps/sdk.js` 요청이 401이면 2·3·4단계 중 하나가 빠진 것이다.

## 7. 무료 여부

카카오맵 JavaScript SDK는 무료이고 일 호출 한도가 따로 없다(지도 표시 API). 네이버·구글과
달리 과금 계정 연결이 필요하지 않은 것이 카카오를 선택 가능한 제공자로 둔 이유 중 하나다.
단 이 무료는 *지도 표시*에만 해당한다 — 좌표를 이름으로 바꾸는 일은 이 앱에서 카카오가
아니라 네이버 지역검색이 하므로, 이 키의 한도와는 무관하다.
